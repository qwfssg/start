## 预防手段汇总

把上面 17 条事故的教训收敛成 5 条工程纪律（全部已落在本仓库工具里）：

1. **每条工具都输出数字指标，人只核对数字、不做像素级猜测**。抠图逐帧打印背景色/容差/覆盖率/主体 px/域数/补洞 px/内容框/边缘绿 %（docs/02 规则 11）；打包复测脚底跨度/触边/空格；embed-sheet 超限时打印实际 base64 体积。贯穿性设计原则：制作者可能看不见图（README.md:6-8）。
2. **report.txt 留档，结论可回溯**。每次实跑的逐帧指标 + 组汇总写进输出目录（examples/keyed/report.txt 即样例）；处方（presets.json）的 why 字段必须带实测数字，"为什么这样配"三年后还能复核。
3. **回读成品独立复测，不信任内存变量**。打包后从成品图集回读复测（而不是用打包过程中的中间变量自证）；水印修复后逐帧回读 + 修前/修后对比图（cmp2）；冒烟用真实 meta 跑引擎断言状态可达。
4. **干净克隆测试**。生成物（sheet.js/client.js）不入库，用 git ls-files 清单复制到临时目录验证"克隆即可构建"（README.md:87-90；已实测：67 文件清单 → 临时目录 build.ps1 -Demo 6/6 全绿、smoke 142/0、sheet.js+client.js 现场重建）；异规格素材（1088×2176 之类）在入口就被尺寸门槛隔离，不进主流水线。
5. **探针与 UI 标签同步改，白名单改动走清单**。改菜单标签必须同步改 verify.mjs/smoke.mjs 断言，带动态数字的标签用前缀匹配；新增状态按五处清单核对（NAMES / stateDef / menuItems / meta.states / verify 断言），漏一处就有探针兜底报 FAIL。
