### 状态切换规则（setState，`pet.js:423-440`）

- 未知状态名一律回落 `idle`（`:425`）。
- **react 单次播放保护**：react 且 `loop:false` 且未播完（`frames.length/fps×1000` ms）时，非 force 切换被忽略（`:428-430`）。
- **busyLocked()**（`:421`，函数体就一行）：`st.name === 'working' || st.name === 'wait'`。语义＝"会话占用中"：
  - 非 force 的 `idle`/`sleep`/`walk`（非拖拽中）切换被拒（`:431-433`）——防止空闲漫游和自动睡眠抢占工作状态；
  - 拖拽期间只挪位置不换状态（`:670`）；
  - react 打断 busy 时记录 `pendingAfter = 原状态`，播完回去（`:434`、`:442-447`）；
  - 漫游启动/停止都要过 `!busyLocked()` 门（`:504`、`:629-630`）；
  - 任务完成只在 working/wait 时才庆祝（`:471`）。
  - `force:true` 绕过以上全部保护（`:428/:431`；菜单 pickMode、notify、Ctrl+Alt+W 都用 force）。
- 切到非 walk/sleep 状态会 `stopRoam()`（`:436`；注意 sleep 被豁免，见 §4 边界行为）。
- **next 兜底**：默认 `next:'idle'`（`:172`）；meta 的 next 必须是字符串且在 NAMES 白名单内才采纳（`:188`）。**两套 meta 实例（pet.json / pet-hd.json）都没有任何 next 字段** ⇒ 现状所有状态播完一律回 idle。单次推进只对 react 生效：tick 里 `st.name==='react' && !def.loop` 才调 `advanceOneShot`（`:626`、`:442-447`），其它状态即使 meta 配了 `loop:false` 也不会自动转场（当前实现的如实描述）。
- 优先级注释原文：`react > (wait|working 由会话事件驱动) > 菜单指定 > 漫游/空闲`（`pet.js:418-420`）。
- 动画时钟：唯一 rAF 主循环（`pet.js:616-635`），`performance.now()` 推帧、dt 钳 100ms（`:623`）、`document.hidden` 整链停摆（`:622/:637/:643-648`）、不用 setInterval（`:7-8` 注释）。对外接口仅 `start/stop/state/setState/notify/bubble/refresh/bounds/sheetInfo`（`:1023-1033`）。

## 2. 会话联动

- **事件链**：探测源发 `CORE.emit("session", {phase, via})` → boot 订阅转 `PET.notify(detail.phase)`（订阅点 `dsh-pet-bg/src/boot.js:399-408`；处理 `pet.js:461-481`）。
- **phase 'start' / 'message'**：`markActivity()` + 强制进 `wait`，并挂单一计时器 `WORK_DELAY_MS = 1500ms` 后若仍在 wait 则强制进 `working`（`pet.js:24`、`:463-468`；计时器 key 'work'，重复 notify 重置不堆积 `:466` 注释）。**1.5s 的真实值就是 1500ms**（`pet.js:24`，注释标注"需求 2.5 的原话时长"；`pet.js:741-743` 菜单注释同说法；实测探针记录见 `dsh-pet-bg/README.md:137-138`）。
- **phase 'end'**：清计时器；仅当当前是 working/wait 时 → `pendingAfter=null`（庆祝完回 idle 不回 working）→ `enterState('react')` + `CORE.play('done')` + 气泡「搞定 ✅」3200ms（`pet.js:469-476`）。
- **phase 'error'**：水平抖动 420ms（`shake` `pet.js:65`、`:477-480`、`:555-558`）+ 气泡「出错了 ❌ 看看日志」4000ms。**如实说明：当前 src 里没有任何发射点**——boot.js 只发 'start'/'end'（`boot.js:32/:146/:155/:260/:301`，grep 核实），'error' 与 'message' 是 notify 的预留分支。
- **探测三档阶梯**（`boot.js:15-18` 注释、`:65-69` 注释；选择顺序 `:438-442`，T1 失败才 T2，绝不同时开防双报 `:438-439` 注释）：
  - **T1** 官方通路：`services.remote.$on("api-session/status", (sessionId, running) => …)`，running 翻转即发 start/end（`boot.js:27-41`）；inject 声明 `["remote","sessions","slots"]`（`boot.js:7`）。
  - **T2** DOM 观测：正向信号"存在即运行中"——停止按钮选择器组（`boot.js:70`）、busy 标记组 `aria-busy/data-streaming/data-running/.dsh-streaming`（`:71`）、按钮文字匹配「停止/中断/取消任务/stop/cancel/interrupt」（`:87-101`）。MutationObserver（`:175-182`）+ rAF 节流（`:165-170`）+ **700ms 兜底轮询**（`:183-186`，注释记录了纯 MO 漏回调导致桌宠不庆祝的实测教训）。结束判定：450ms quiet 期 + **只复查"当初让我进 running 的那个信号"是否消失**（`:114-131`、`:147-158`）。
  - **T3** 手动：菜单模式项 + `Ctrl+Alt+W` 在 working/idle 间强制切换（`boot.js:192-205`）。
- **派活回流**：派活成功也会发 `session {phase:'start'}`（`boot.js:260/:301`），桌宠随后进 wait→working。

## 4. 漫游（roam）

- 开关字段 `pet.roam`（默认 true，`core.js:77/:101`）；菜单第 19 项翻转（`pet.js:785-789`）。
- **与模式选择的互斥**：手动选任何非 idle 模式 → `pickMode` 自动把 `pet.roam` 写 false（`pet.js:744-751`）；选「待机眨眼」→ 写回 true。这就是"手动选模式自动关漫游，否则漫游抢走选择"的实现（注释 `:741-743`）。
- 启动条件（全部满足，`pet.js:630`）：`!roam && !drag && !reducedMotion && st.name==='idle' && pet.roam && !pet.locked && 无输入>60s（IDLE_ROAM_MS :22）&& 过了冷却期`。
- 行为：只走水平线（y 不变，"它自己那条地面线" `:540-546`）；速度 `ROAM_SPEED=34px/s × fpsScale()`（`:25`、`:542`，脚步与滑步同倍率防"溜冰" `:26-27` 注释）；目标随机 0.04~0.96 且至少走 40px，否则本轮不出门（`:507-513`）；到位随机停 1.2~3.5s 播 idle（`:548-552`），70% 概率再走一段（`:527-533`）；轮次间冷却 15~45s（`:529/:536`），离边界太近冷却 20s（`:517`）。**冷却绝不动 idleAt**——否则 300s 自动睡眠永远到不了（`:62` 注释）。
- 持久化：停哪儿存哪儿——`stopRoam` 立即写 `pet.x/facing`（`:505`），到位时 debounce 写 `pet.x`（`:551`）。
- 300s 无输入自动 `sleep`（`IDLE_SLEEP_MS :23`；tick `:631` 先 `stopRoam()` 再 `enterState('sleep')`，注释"睡觉不许顺路漫游"）；任何 pointer/wheel/键盘输入立即唤醒（`markActivity :496-499`，绑定 `:653/:663/:703/:719/:870/:877/:950/:951` 与 notify `:464`）。
- **边界行为（读码结论，如实记录）**：`setState` 对 sleep 豁免 stopRoam（`:436`），且 tick 里 `tickRoam` 不受 sleep 门控（`:633`）⇒ 若在漫游行走中手动选「睡觉休息」，本轮漫游不会取消：桌宠会以 sleep 姿态继续平移，到位后被 `enterState('idle')`（`:552`）改回 idle。自动睡眠路径无此问题（`:631` 先停漫游）。

## 5. 速度（fpsScale）

- **存储层**：sanitize 白名单 `fpsScale = clamp(值, 0.15, 2, 1.4)`，缺省即 1.4（`core.js:98-100`，注释原话："缺省 1.4：配置里从未存过 fpsScale 时，这里才是真实生效的默认值（用户反馈'不流畅'后由 0.6 提速；已存值优先）"）。
- **pet.js 兜底常量到不了**：`DEF_FPS_SCALE=1.4` 与 `fpsScale()` 的 typeof 兜底（`pet.js:31-35`）在 sanitize 之后永远拿到 number，兜底分支实际不可达——`pet.js:29-30` 注释明说"真默认值在 core.js sanitize 里…那边才是实际生效的一处"；踩坑全记录见 docs/08 第 10 条。改默认速度必须改 `core.js:100`。
- **UI 层钳位**：菜单加速/减速步进 `SPEED_STEP=0.2`、钳 `SPEED_MIN=0.4 ~ SPEED_MAX=2.0`、结果四舍五入到 0.1（`pet.js:814-819`；`:814` 注释：这是"菜单步进的实用钳位"，core 的 0.15~2 是存储层保护，两层并存）。即：UI 最低只能调到 0.4×，但控制台 `CORE.set({pet:{fpsScale:0.15}},true)` 能压到存储层下限（`pet.js:28` 注释给了试法）。
- **立即生效**：fps 每帧现算 `meta.fps × fpsScale()`（`pet.js:183`），stateDef 在 tick（`:625`）与 drawStateAt（`:565`）每帧重调，无缓存可失效（`:777-778` 注释；注意该注释内引的 "pet.js:380/440" 是旧行号）；stepSpeed/resetSpeed 另补一次即时重绘（`:818/:822`）。漫游步速同倍率（`:542`）。

## 6. 尺寸与几何（scale / display / PAD / 锚点）

- `pet.scale`：范围 0.5~2.5（`pet.js:18`；存储层同钳 `core.js:94`）。滚轮 ×/÷ `WHEEL_STEP=1.08`（`pet.js:19/:717-727`，落盘 immediate `:726`）；菜单 ×/÷ `MENU_STEP=1.12`（`:20/:774-775/:800-807`）；尺寸档 `[0.75, 1, 1.25, 1.5]` 循环（`:37/:808-813`）。缩放零漂移：cfg.x/y 本来就是脚底中心，layout 始终把脚底钉回该点（`:714-716` 注释）。
- **PAD=1.25**（`pet.js:17`）：画布 = display cell × scale × 1.25，25% 留白全放头顶给跳跃/粒子（`:384-385`）。
- **元素 240×280 基线**：两套素材 `meta.display` 都是 192×224（`petwork/out/pet.json:10-13`；`dsh-pet-bg/assets/pet-hd.json:10-13`）⇒ scale=1 时元素恒 240×280，高清热切换零跳变（`pet.js:107-109` 注释；geometry `:377-388`：`W=dspW×scale×PAD`，`dh=dspH×scale`，`H=dh×PAD`）。
- 绘制宽按 cell 纵横比 uniform：`dw = dh × (cw/ch)`，绝不拉变形（`:383`）；cell px→CSS px 系数 `k = dh/ch`（`:386`），内嵌版 k=224/150≈1.4933，内容盒 98×118 上屏 ≈146.3×176.2（`dsh-pet-bg/README.md:164-166`）。
- **display 补偿机制**：meta 有 `display{w,h}` 就用它当"显示用 cell 尺寸"；旧图集没有则回落 `cell × displayScale`（displayScale 缺省 1），与旧版行为一致（`pet.js:155-168`）。
- **锚点=脚底中心**：`bx = x0 + ax×k`，`by = y0 + ay×k`（`:387`）；stage.left/top = 脚底像素 − b（`:407-408`，注释"让脚底锚点精确落在 cfg.x/y"）。
- **baselineY 优先于 anchor.y**：`aySrc = isNum(m.baselineY) ? m.baselineY : px(a.y, c.h, c.h)`（`pet.js:154`；内嵌 baselineY=134、高清=204）。anchor 支持两种写法：0..1 视为 cell 内比例、否则视为像素（`:150-153`，判定规则注释在案）。
- DPR：clamp 1~2（`:102`），canvas 物理像素 = 逻辑 × dpr（`:398-401`），每帧 `setTransform` 顺带抗外部重置（`:568`）。
